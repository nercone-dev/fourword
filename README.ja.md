# FourWord
時系列ソートが可能な新しいランダム識別子の生成方式

## 概要
新しいランダム識別子の生成方式です。
データベースの主キーなどで使用することを想定して設計しました。

先頭にタイムスタンプがあり、テキスト化で文字セットとしてBase32 Hexを使用しているので、時系列順でのソートが可能です。
パディングには`=`の代わりに`Z`を使用しているため、英数字を使える場所であれば使用できるはずです。

できる限り衝突の可能性を低くしつつオーバーフローも防ぐために、タイムスタンプは固定ではなく全体のビット数の1/4になっています。
これにより全体のビット数を多くするだけで、タイムスタンプがより長くなり、より長く継続して利用できるようになります。

ただし代わりに、ビット数を多くすると、タイムスタンプ部分の先頭に無駄な連続した0の部分が発生します。

## 語源
Fourの部分は、タイムスタンプがビット数の1/4を占めることからです。
それと「Forward」と掛けています。

## Pythonライブラリ
```sh
# Install using pip
pip3 install fourword

# Install using uv
uv pip install fourword

# Add to Project using uv
uv add fourword
```

```python
from fourword.lib import FourWord

fourword = FourWord(bits=256)
print(fourword.text)
print(fourword.timestamp.isoformat())
```

```sh
# Show usage
fourword --help
# Generate FourWord ID with default 256 bits
fourword g
# Generate FourWord ID with custom 512 bits
fourword g --bits 512
# Generate FourWord ID and Show with details
fourword g --detail
# Decode FourWord ID and Show with details
fourword i 32OD9FEO1M8G0I7A0CMGMC599N14NJQ9SQAJPT3TRATETRAMBKTGZZZZ
```

Pythonでは`fourword`ライブラリを使用してFourWordを生成/分析できます。

また、Pythonライブラリには`fourword`CLIコマンドも付属しています。

## 仕様
FourWordは次のようなバイト列(ビッグエンディアン)で表現されます。

```
[ (全体のビット数/4) ビットのUNIXタイムスタンプ(UTC,ns) ] + [ (全体のビット数/4*3) ビットのCSPRNG ]
```

例えば全体のビット数が256ビットの時、タイムスタンプは64ビット、ランダムな部分は192ビットになります。

比率が固定なのは、IDからタイムスタンプを取得する際、セパレータを設けなくても確実な長さが簡単にわかるようにするためです。

### 形式
FourWordは他の方式と違い、テキスト以外の形式にも対応しています。

**Text**

```
32OD9FEO1M8G0I7A0CMGMC599N14NJQ9SQAJPT3TRATETRAMBKTGZZZZ
```

テキスト化にはBase32 Hexのようなものを使用します。

前述した通り、パディング文字として`=`の代わりに`Z`を使用しますが、それ以外はBase32 Hexと同じです。

**Compact Text**

```
5r0NHGp8VYQuT2sVX1OZNDXn9XRg3qar5CsaahtCi7f
```

文字セットとして`0-9A-Za-z`のBase62を使用します。
バイト列をビッグエンディアンの多倍長整数として解釈してBase62変換します。
先頭には`0`でゼロ埋めを行い、同一ビット数では常に固定長になります。

Text形式と比較して約76%の長さで表現できます。
例えば256ビットでは、Text形式の場合56文字ですが、Compact Textの場合43文字に収まります。

ただし、Base62は2の冪でないためビット演算が使えず、デコードには多倍長整数演算が必要です。
また、大文字・小文字を区別しない環境では使用できません。

**Readable Text**

```
32od9feo-1m8g0i7a-0cmgmc59-9n14njq9-sqajpt3t-ratetram-bktg
```

Text形式をベースに、人間が読みやすいよう以下の変更を加えたものです。

- 文字セットを小文字化 (`0-9, A-V` -> `0-9, a-v`)
- パディングを省略 (ビット数が固定のため、デコード時に復元可能)
- 8文字ごとにハイフン(`-`)を挿入

**Decimal**

```
11167941737807864551984210163608533232246628802352979308802140359026483289403
```

単にバイト列を2進数として解釈して10進数にするだけです。

**Hex**

```
18b0d4bdd80d910048ea032d0b30a94dc24bcf49e6953cf47ddabaeeed565d3b
```

Decimalと同様、単にバイト列を2進数として解釈して16進数にするだけです。

### 衝突確率
タイムスタンプが異なるIDは衝突しません。以下は最悪ケース(全IDを同一ナノ秒内に生成)の場合の値です。

| ビット数 | ランダムビット幅 | 衝突確率 10⁻¹⁸ に必要なID数 | 衝突確率 10⁻⁹ に必要なID数 | 衝突確率 50% に必要なID数 |
|---:|---:|:---|:---|:---|
| 256 | 192 bit | 約 1.12 × 10²⁰ | 約 3.54 × 10²⁴ | 約 9.33 × 10²⁸ |
| 512 | 384 bit | 約 8.88 × 10⁴⁸ | 約 2.81 × 10⁵³ | 約 7.39 × 10⁵⁷ |
| 768 | 576 bit | 約 7.03 × 10⁷⁷ | 約 2.22 × 10⁸² | 約 5.85 × 10⁸⁶ |
| 1024 | 768 bit | 約 5.57 × 10¹⁰⁶ | 約 1.76 × 10¹¹¹ | 約 4.64 × 10¹¹⁵ |
| 1280 | 960 bit | 約 4.41 × 10¹³⁵ | 約 1.40 × 10¹⁴⁰ | 約 3.67 × 10¹⁴⁴ |
| 1536 | 1152 bit | 約 3.50 × 10¹⁶⁴ | 約 1.11 × 10¹⁶⁹ | 約 2.91 × 10¹⁷³ |
| 1792 | 1344 bit | 約 2.77 × 10¹⁹³ | 約 8.76 × 10¹⁹⁷ | 約 2.31 × 10²⁰² |
| 2048 | 1536 bit | 約 2.20 × 10²²² | 約 6.94 × 10²²⁶ | 約 1.83 × 10²³¹ |
